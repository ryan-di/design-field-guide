# Chapter 10 · Did it work?

> Evidence boundary: this is a learning guide. Its demos and product examples are illustrations written for the book, not verified product documentation, so check a product’s own docs before citing how it behaves. Tools named in it are 2026 examples, not endorsements.

You press a button and nothing seems to happen, so you press it again, or you decide it’s broken and give up. Jakob Nielsen put this first in his ten usability heuristics, as visibility of system status: people should always know what the system is doing, and hear back quickly. The patterns below answer “did it work?” at the right moment and in the right place, with Part 3 components like the [spinner](https://ryan-di.github.io/design-field-guide/#spinner), the [progress bar](https://ryan-di.github.io/design-field-guide/#progress-bar) and the [toast](https://ryan-di.github.io/design-field-guide/#toast).

## Entries

- [Instant feedback](../entries/pat-instant-feedback.md): Instant feedback means the screen answers an action right away: a pressed button changes, a ticked box shows a tick, a save says “Saving…”.
- [Optimistic UI](../entries/pat-optimistic-ui.md): Optimistic UI shows the result of an action before the server confirms it.
- [Background work](../entries/pat-background-work.md): Some work takes longer than people want to wait, such as an upload, an export or a backup.
