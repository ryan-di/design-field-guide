# Chapter 26 · Write the brief agents build from

> Evidence boundary: this is a learning guide. Its demos and product examples are illustrations written for the book, not verified product documentation, so check a product’s own docs before citing how it behaves. Tools named in it are 2026 examples, not endorsements.

An agent builds what you write down, not what you meant. A good brief names the problem, the context to use and how you’ll check the result.

## Entries

- [Problem brief](../entries/eff-brief.md): A problem brief is a short note written before anyone builds.
- [Context pack](../entries/eff-context-pack.md): A context pack is what a new teammate would need on their first day: design tokens, components to reuse, copy rules, examples of good screens, repo conventions and the design frames.
- [Definition of done](../entries/eff-definition-of-done.md): A definition of done is the list of checks a change must pass before you call it finished.
