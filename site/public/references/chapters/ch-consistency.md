# Chapter 3 · Same thing, same look, same place

> Evidence boundary: this is a learning guide. Its demos and product examples are illustrations written for the book, not verified product documentation, so check a product’s own docs before citing how it behaves. Tools named in it are 2026 examples, not endorsements.

People learn a product one screen at a time, and they bring habits from every other product they use. The entries below cover spotting drift, keeping shared values in one place, and breaking the rule only on purpose.

## Entries

- [Internal & external](../entries/good-consistency.md): Consistency means one action has one look, one concept has one name, and the same buttons sit in the same order everywhere.
- [Design tokens](../entries/good-design-tokens.md): A design token is a shared value with a name, such as a corner radius, a spacing step, a color or a text size.
- [Break it on purpose](../entries/good-break-on-purpose.md): Consistency doesn’t mean everything looks the same.
